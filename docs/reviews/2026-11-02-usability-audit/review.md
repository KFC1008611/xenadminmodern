# 日常操作中的细节问题复查

本轮从连接入口、统一资源列表、VM/主机详情、任务读取、存储/网络入口、模板设置与告警表单检查日常使用问题，重点检查错误后的继续操作、保存结果、异步请求和表单可用性。修复集中在已复现的连接、模板与告警流程；不将一次代码检查解释为全部功能无缺陷。

## 已复现并修复

| 问题 | 用户受到的影响 | 修复 |
| --- | --- | --- |
| 保存的密码被 XAPI 拒绝后，只有钥匙串读取失败才展开密码输入 | 再次点击连接仍使用旧密码；已保存服务器窗口不能直接更正 | 两个连接入口均识别 `SESSION_AUTHENTICATION_FAILED`，在原卡片重新输入，成功后沿用原 profile 保存 |
| 模板始终先写 CPU 最大数，再写启动数 | 将 8/8 调成 2/2 时，第一步就违反 XAPI 约束而失败 | 按当前启动数和目标最大数安排顺序；提交前校验完整目标配置 |
| 模板各字段独立写入，缺少最终结果读回 | 名称可能已改而 CPU/内存失败；响应丢失或服务器未应用时反馈不准确 | 先校验后写入，丢失响应只读取、不重放写请求；按池连接与模板 UUID 核对全部变更，报告未完成字段和实际 CPU 配置 |
| 模板和告警保存时仍能更改字段；告警可点取消或重复提交 | 草稿与已提交内容不同，创建规则可能重复 | 保存期间冻结草稿与关闭入口，加同步提交保护；模板部分应用或读取故障保留具体错误并禁止沿用旧表单重交 |
| 告警输入框把阈值限制为 5% 或 1 MiB/s 的倍数 | 83%、82.5%、10000000 B/s 等后端支持的配置被浏览器阻止保存 | 取消额外步长限制，沿用实际阈值、持续时间范围校验 |

模板设置窗口正文使用独立滚动区，错误区和操作栏保留在正文之外。人工查看初次截图时发现 fieldset 在窄窗口的滚动布局会与错误区重叠，调整为外层容器负责滚动后重新完成全部场景；追加几何检查，验证正文、错误区和按钮不相互覆盖。已确认保存后的清单刷新故障单独显示，旧请求不能关闭新模板窗口。

初查的添加服务器关闭与任务清单错误提示已有处理：连接回调使用提交前的关闭函数，任务域通过全局资源读取栏展示错误。没有将这些初步疑点计入缺陷或据此改动。

## 审查问题修复：字段写入之间连接变化

审查补充复现了名称已写入、简介尚未写入时连接身份变化的路径：原实现直接抛出普通错误，经 IPC 转为 `UNKNOWN_ERROR`，前端连接状态尚未刷新时会重新允许提交旧表单。现统一返回 `RESOURCE_RESULT_READ_FAILED`，停止后续写入及旧表单提交，要求重新读取模板后再编辑。

新增服务回归在修复前准确复现错误代码丢失；修复后通过，并核对名称只写入一次、简介未写入且不再读取旧连接。界面回归使用真实 IPC 错误序列化，覆盖连接变化原因仍可见、字段和保存按钮保持禁用，以及再次点击不会提交。79 项相关测试、Node/Web 类型检查、lint 和差异格式检查通过；本次追加修复未重跑上述历史全量与界面截图检查。
