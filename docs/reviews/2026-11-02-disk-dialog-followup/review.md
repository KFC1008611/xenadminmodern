# 磁盘创建与移动的细节复查

本轮沿参考对话的断线恢复和日常操作问题，检查磁盘新建、移动及相关异步窗口。保留工作区已有的连接、模板和告警修改；本轮新增修复集中于两个磁盘窗口。

## 用户会遇到的问题

| 问题 | 影响 | 修复 |
| --- | --- | --- |
| 移动窗口从全部 SR 中默认选择第一个非原仓库，未排除 ISO 库 | 实际 `sr.service.getAllSrs` 会返回 ISO 库；默认选中后，被既有移动服务拒绝 | 新建和移动均排除 `iso`、`udev` 及 `content_type=iso`；移动还排除当前 SR，空目标显示具体原因 |
| 移动目标清单读取失败后没有原地重读入口 | 临时断网后必须关窗重开 | 保留具体错误，提供重新读取按钮，成功后恢复选择和提交 |
| 移动请求报错后重新开放提交，包含服务器 Task 结果读取失败 | 用户可能再次发送原磁盘移动请求 | 保留原错误及核对步骤，冻结原提交，允许关闭后重新读取磁盘和存储清单 |
| `VDI_CREATED_ATTACH_INCOMPLETE` 被统一显示为“创建失败” | 已创建并保留的磁盘被当成未创建，容易再次建盘 | 显示磁盘已创建、附加未完成，或具体的附加结果读取失败；保留磁盘引用并刷新清单 |

## 组件边界补强

用受控回调和延迟响应补充复现了两个窗口的边界：同步或异步父刷新报错、连接生命周期变化、关闭重开、切换目标、同一磁盘记录更新，以及同一渲染内的重复点击和提交后立即关闭。

创建结果与刷新错误分别保存，同步抛错和异步拒绝均不覆盖已确认的创建结果。窗口读取和提交绑定原连接代次；旧响应不能回填、刷新或关闭新对象窗口。已提交请求只发送一次，连接变化后显示静态读取故障；没有自动重发写请求。同一磁盘更新记录保留已选移动目标，新建草稿在重新读取仓库时保留。

这些组件边界回归不等于已在所有当前路由中复现同样的问题；VM 详情原有的对象/连接键也继续提供上层隔离。新增保护覆盖组件自身及其回调契约。

## 依据

- [XAPI 存储设计](https://github.com/xapi-project/xen-api/blob/master/doc/content/xapi/storage/_index.md)：ISO SR 中的 VDI location 表示 ISO 名称，区别于普通磁盘存储。本轮通过 Context7 读取该资料及 VDI migration 的目标仓库说明。
- [Xen Orchestra 术语](https://docs.xen-orchestra.com/glossary)：区分 SR、VDI、VBD，并将 ISO 仓库用于安装介质。本轮通过 Context7 读取。
- 本地 [XenAdmin SR 扩展](../../../refs/xenadmin/XenModel/XenAPI-Extensions/SR.cs) 的 `SupportsVdiCreate` / `SupportsStorageMigration` 按 `content_type` 排除 ISO 内容库；另有驱动能力判断。本轮读取相关实现，仅修正当前窗口遗漏的明确不支持仓库，不声称实现完整驱动能力筛选。
- 当前主进程 `vdi.service` 已在创建和移动前拒绝 ISO/udev/ISO 内容仓库，窗口筛选与其对齐。共享 SR 类型补充已经透传的可选 `content_type` 字段，没有新增 IPC 接口或配置项。
