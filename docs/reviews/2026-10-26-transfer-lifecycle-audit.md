新增确认并修复：

| 问题 | 修复与验证 |
| --- | --- |
| 导出收到非 200 响应后只等待 end，未处理错误响应中断。对端断开或用户取消后无法进入原 Task 核对，任务卡在运行/取消中。 | 统一处理文本响应的 error、aborted 和提前 close。HTTP 回环故障注入在修复前分别复现断开与取消卡住，修复后均按原 Task 进入明确终态，不生成最终文件。 |
| 上传源字节数少于 Content-Length 时仍结束请求，服务器等待剩余内容，客户端只等超时。源流无 end/error 直接关闭也可停滞；源文件增长则可能发送多余内容。 | 共用 HTTP 通道核对源流长度和意外 close，立即终止该次请求，把提前响应之后的错误也交给响应消费方。覆盖响应头前/后的短流、超长流及无错误的意外关闭，不自动重传。 |
| 导入确认和导出错误响应无限缓存，异常响应可持续占用内存并延迟任务核对。 | 文本响应限制 64 KiB。回环服务器持续保持超限响应不结束时，导入/导出均能停止读取并核对原 Task；每个操作只有一次 HTTP 请求。正常 XVA 文件仍流式读写，不受此限制。 |

TLS 握手停滞、持续下载的空闲超时、重定向、TLS 信任及禁止降级、取消、导入后置条件、导出文件完整性与 RRD 读取均纳入回归。TCP 已接通但不完成 TLS 的测试通过，未修改握手实现。未发现导出成功流与 RRD 消费路径存在此前“收到成功头立即关闭上传”的同类逻辑。
