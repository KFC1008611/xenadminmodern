# 2026-10-23 性能补充优化

本轮处理后续复查确认的四项瓶颈：满容量指标缓存反复排序、VM 详情重复下载完整 RRD、慢监控查询叠加、首窗创建前同步恢复大指标快照。原工作区已有逐页 UI 修改，本轮保留这些修改；未提交、安装应用或访问真实 XCP-ng。

## 结果

| 场景 | 修改前 | 修改后 |
| --- | --- | --- |
| 缓存已有十万条，500 台 VM 各写入两个新样本，三次测量 | 同步耗时 2046–3240 ms | 同步耗时 2.05–2.73 ms |
| VM 已完成后台初始化，再执行三次历史查询 | 又下载三次完整 RRD | 额外完整 RRD 下载 0 次 |
| VM 历史响应耗时 90 秒，模拟运行 60 秒 | 三个请求同时在途 | 一个请求在途 |
| 主机与 VM 各十万条、约 80.6 MiB 快照恢复，三次测量 | 主线程同步恢复 251–287 ms | 发起恢复 0.26–0.32 ms；恢复期间 1 ms 心跳最大间隔 9.3–10.2 ms；后台全部完成 612–642 ms |

快照恢复总时间增加，但读取和 JSON 解码移出主线程，索引分批建立，首窗无需等待全部历史。发起时间、心跳最大间隔和全部完成时间是三个不同指标，不能将 0.3 ms 当作完整恢复时间，也不能将心跳间隔直接解释为首窗显示时间。此处未实测 Electron 冷启动到首帧时间。

测量使用 Node 24.22.0 的实际数据库服务；输入字段、样本规模与前次复查相同，三次测量保留原始值。VM 请求场景使用实际调度器、解析器和组件，远端网络及 IPC 延迟采用模拟值。基线见 evidence 中无 `-after` 的 JSON，优化后见对应 `-after` 文件；数据库探针源码以 `.txt` 保存。早期复查的全量调查文件继续留在临时目录。

## 实现与行为

指标使用带键索引的时间戳最小堆淘汰最旧样本，新增样本最多执行一次增量淘汰，不全量排序或复制缓存。主机与 VM 各十万条硬上限、七天保留策略、资源池隔离、重复时间戳替换均保留；乱序样本不会挤掉更新的数据。查询仍按时间排序，快照文件仍为原有 version=1 的 hosts/vms 数组格式。定期过期清理直接从最旧项移除，降采样后重建索引。

VM 详情已有数据时直接查询本地历史，后续样本由后台增量采集更新。直接打开详情、后台采集尚未启动时，为原连接启动既有采集器。缺少历史时才按需下载归档，且与同一 VM 的后台初始化共用在途请求；失败后允许重试。连接代次、客户端实例和资源池身份变化后，旧请求不能写入历史；停止采集会中止在途归档。

VM 页面的下一次自动查询在本轮完成后等待 30 秒。手动刷新合并，切换时间范围或连接时等待前一请求结束，只执行最新查询；旧结果和卸载后的结果不更新页面。关闭自动刷新清除下一轮定时器，当前请求结束后不再自动发送。读取失败保留已有数据并显示原始原因，成功重读后清除对应失败信息。

启动时小规模告警配置继续按原规则读取；大指标文件由 Node 工作线程读取和解码，每 256 条带确认地发送到主线程，索引建立之间让出事件循环。所有指标查询、采集和告警计算等待同一个恢复任务，完成后才发布完整历史；恢复失败不返回假空历史、不覆盖原文件，修复文件后可重试。关闭应用等待恢复和最新保存版本。

工作线程脚本作为固定源码随主进程打包，避免新增运行时 TypeScript 加载器或独立构建入口。工作线程只读取本机指标快照，不执行快照内容；消息按批确认，避免一次复制整个对象图。

## 回归与验证

新增回归覆盖满缓存小批写入、乱序及重复样本、随机序列淘汰模型、恢复期间查询、恢复分批与让出事件循环、损坏与不支持版本的文件保护、关闭期间恢复、后台与按需归档合并、直接详情入口、失败重试、连接替换与停止后的晚到响应、90 秒慢请求、时间范围合并、卸载取消及页面错误恢复。

当前完整门禁及构建结果见本目录的 verification.json 和 docs/validation.md。性能数字来自本机合成场景，不代表真实资源池、已安装应用或长期运行验收。

## 资料

[XAPI 指标接口](https://xapi-project.github.io/xen-api/metrics.html)区分完整 RRD 与用于交互图表的增量更新；本轮复用已有 `/rrd_updates`。工作线程使用 [Node worker_threads](https://nodejs.org/docs/latest-v24.x/api/worker_threads.html) 的 workerData、消息与退出事件。主进程响应性及启动测量遵循 [Electron 性能建议](https://www.electronjs.org/docs/latest/tutorial/performance)。
