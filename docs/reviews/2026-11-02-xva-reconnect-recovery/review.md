# XVA 上传断网后的任务恢复

用户反馈上传 `2026.xva` 时网络中断，恢复网络并重新连接原资源池后，导入窗口仍停在恢复提示并持续显示不定进度。

## 已确认的客户端原因

持久导入记录绑定断网前的本地连接 ID。重连可能生成新的连接 ID，旧连接的恢复查询失败后，后续轮询仍只使用旧 ID。若重连通知到达时旧核对还在运行，新通知会被在途保护跳过，之后没有途径切换到同池的新连接。

新增回归在修改前复现两种情形：原池已经通过新 ID 连接，以及重连通知与旧查询重叠。两项均保留旧连接 ID 和 `unknown` 状态；不同池保护用例通过。见 [修改前复现结果](baseline-reproduction-gate.json)。这确认了源码中的恢复缺陷，不能据此确定本次真实服务器 Task 的终态。

## 修复

每轮恢复重试重新寻找管理连接：原连接仍属于原池时优先沿用；旧 ID 失效时按持久保存的原池 UUID 查找已连接的原池，继续读取原 Task。缺少池身份或只有其他池连接时不推断目标。导入、导出共用此连接选择规则。

恢复本地记录的提示改为“本地导入记录已恢复”，避免推断应用发生过重启。导入窗口和后台面板在任务无法读取时显示静态原因，不再持续滚动进度条；窗口只显示一次具体原因。规范和桌面工作流同步。

XVA 上传使用 HTTP PUT `/import` 并关联 XAPI Task，现有协议没有断点续传流程。网络恢复后继续核对原 Task，不自动重新上传。原任务明确失败或取消的回归只调用 `task.get_record` 及终态后的 `task.destroy`，不新建任务、重新上传或重放配置。依据见 [XAPI 导入导出协议](https://github.com/xapi-project/xen-api/blob/master/doc/content/xen-api/topics/importexport.md)。
