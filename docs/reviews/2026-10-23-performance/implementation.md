# 2026-10-23 性能优化

针对本轮确认的五项瓶颈完成源码优化。原工作区已有大量其他未提交修改，本轮未提交或安装应用，也没有向真实资源池发出请求。以下数据来自本机合成数据、真实调度器、真实存储服务和生产模式 React 组件。

## 修改与实测

| 场景 | 优化前 | 优化后 |
| --- | --- | --- |
| 500 台 VM，每次 RRD 请求延迟 1 秒，运行 90 秒 | 4 轮历史扫描叠加，峰值并发 20，请求 920 次 | 单轮扫描，峰值并发 5，请求 455 次 |
| 上述采集停止后再运行 5 秒 | 又发出 100 次请求 | 新增请求 0 次，在途请求结束 |
| 200 台 VM 的增量采集，单次内存记录查询模拟 100 ms | 串行查询 200 次，占用 20 秒，超过 10 秒周期 | 复用同次批量元数据，逐 VM 查询 0 次；模拟至 30 秒时取得 3 轮增量 |
| 60 秒内 600 个完整 VM 事件，关闭其他轮询 | 额外全量 VM 清单读取 74 次 | 额外读取 0 次 |
| 20 万条指标，约 82 MiB 快照，3 次测量 | 同步保存中位 286.8 ms，定时器延迟最大 339.4 ms | 发起保存中位 0.14 ms，异步完成中位 162.4 ms；整个保存期间 1 ms 心跳最大间隔 6.1 ms |
| 2000 台 VM 列表首次同步提交 | 99.5 ms，2000 行，66,052 个 DOM 节点 | 5.8 ms，100 行，3,358 个 DOM 节点 |
| 2000 台 VM，仅更新任务数据 | 提交中位 32.2 ms | 提交中位 0.1 ms |
| 2000 台 VM 全选 | 52.3 ms | 13.9 ms，选中全部 2000 台 |

指标保存前后使用相同字段和数据规模；优化后每次测量先更新一条样本，避免把“无变更跳过保存”算作提速。同步发起时间与异步完成时间分别记录，不能把 0.14 ms 解读为全部序列化和写盘时间。基线只测量首个定时器延迟，优化后增加了整个写入期间的心跳观测，二者不是同一统计量。

页面对照使用 Chrome 156.0.8078.47、1440×900、生产模式 React。100/500/1000/2000 台 VM 均有原始结果，任务更新各测量 3 次，其余页面动作每个规模测量一次；结果用于确认瓶颈变化，不代表跨设备的性能保证。DOM 计数取首次挂载后的页面，批量目标核对清单在选择后仍按完整选择提供。测试对象是实际 `VmsPage`，不覆盖完整 Electron 外壳。

另外在 1024/1280/1440 像素宽度验证 205 条记录翻至末页显示 5 行、下一页禁用，且末页全选仍包含全部 205 台。分页控件在观测位置保持可见，页面无运行错误；这项检查不替代完整应用的响应式验收。

## 实现和边界

历史初始化增加连接代次、跨轮次互斥和取消信号。主机归档成功取得游标、VM 归档成功初始化后不再周期重下；失败保留重试，新出现的运行 VM 继续初始化，重启采集使用新代次。并发限制按连接执行；不同池的请求独立。HTTP 取消不代表取消已经提交的 XAPI 元数据 RPC，旧 RPC 返回后仍通过代次检查阻止后续 RRD 请求和数据写入。

增量数据仍按主机 UUID 隔离，游标只推进到实际观察到的服务器样本。内存上限来自当前批量 VM 记录，保留缺失数据的可用性标记；单 VM 按需读取保留原接口。单元回归覆盖动态内存上限改变、旧代次晚到及初始化失败重试。

事件仅在缺少完整列表字段、缺少对象快照或缺少当前客户机地址时合并读回；不完整快照到达时保留最近完整记录。既有请求版本检查、写后强制读回和连接变更隔离继续生效。运行 VM 的普通完整快照保留同一 Guest Metrics 对象的已有地址，后续周期读取更新地址。

指标持久化按 256 条分片编码，异步写盘后原子替换原有版本化 JSON 文件。取消了每次保存的全量排序和索引重建；容量溢出时只修剪对应样本种类，定期保留与降采样继续执行。单写入器合并请求，保存期间 revision 改变会再次保存，退出等待最新 revision。中途编码或写盘失败保留原快照，错误可见且可重试。回归使用真实临时文件验证格式、0600 权限、中途失败、并发保存及退出期间新增样本。

采用分片异步处理，是因为已测量的瓶颈包括同步文件 I/O、重复索引维护及一次性大 JSON 编码。直接把 20 万个对象传给 worker 仍需在发送端复制，增加峰值内存；本轮先消除重复工作并通过分片让出事件循环。没有实测 worker 对照，不能声称多线程一定更慢。网络请求、批量 RPC 和 DOM 规模分别通过限流、减少查询和分页处理。后续只有解析或降采样的 CPU profile 显示持续长任务时，再考虑将相应纯计算迁入 worker。

VM 列表统一分页覆盖 VM、用户模板和系统模板；筛选回首页、记录减少时夹紧页码。复选框用 Set 查询，数据订阅仅包含 VM/主机及 VM 读取状态。全选、跨页选择和批量操作仍针对完整筛选 VM，未取消任何已有目标核对和状态保护。

## 验证和资料

本轮新增回归覆盖采集并发和停止、归档重试与新资源发现、重启代次隔离、批量内存元数据、事件不放大及缺失信息读回、异步保存和分页选择。完整测试门禁、类型检查、lint、生产构建与最终来源散列记录在 [验证结果](evidence/implementation-verification.json)。

固定 Node 24.22.0、npm 11.19.1 下，最终完整门禁通过 196 个文件、2045 项测试；零失败、零跳过、零 todo、零 warning、零 stderr，严格清单无漂移。Node/Web 类型检查、lint、生产构建和 `git diff --check` 通过。性能及 XVA 相关专项 138 项通过；追加退出完成回调边界后，持久化相关 49 项通过，并再次执行完整门禁。

XVA HTTP 测试的共用资源夹具补齐了当前创建预检使用的 `pool.get_all_records`，导入逻辑未改动。

优化前证据保留在 `evidence/*-results.json`、`metrics-overlap.json`、`event-amplification.json` 和 `incremental-n-plus-one.json`；优化后文件使用 `-after` 后缀。探针源码以 `.txt` 存档，避免进入正常测试集合；生产回归在 `tests/` 并列入严格收集清单。`source-manifest.json` 和 `verification.json` 属于优化前检查，最终状态以 `source-manifest-after.json` 和 `implementation-verification.json` 为准。

参考资料获取记录见 [external-sources.json](evidence/external-sources.json)：[XAPI 指标接口](https://xapi-project.github.io/xen-api/metrics.html)说明完整 RRD 下载开销及增量读取；[XAPI 事件](https://xapi-project.github.io/xen-api/classes/event.html)描述变更对象快照；[Electron 性能建议](https://www.electronjs.org/docs/latest/tutorial/performance)建议避免阻塞主进程和同步 I/O。另对照 [XO 基础设施管理](https://docs.xen-orchestra.com/manage-your-infrastructure/manage_infrastructure)的对象组织。获取 XenCenter 性能页时被重定向到文档首页，因此该响应没有作为具体行为依据。

这些结果不包含真实 XCP-ng 延迟、跨池长期并发、网络带宽或已安装应用验收。启动读取大型 JSON、RRD XML 解析及定期降采样仍有同步计算，尚无证据将其量化为本轮已修复的瓶颈。
