# 导入上传停滞修复（2026-10-26）

当前运行的 `/Applications/xenadmin-modern.app` 导入一个 7,285,716,992 字节的 XVA。本地完整校验已完成，耗时约 52.6 秒；上传记录在最初 11 毫秒读出 1,638,400 字节后不再增长。只读 TCP 采样显示导入连接两次采样的发送量均为 1,643,342 字节，应用也已没有打开该 XVA 文件。面板持续增加耗时后，以固定字节数除以总耗时，显示出不断下降的平均速度。

已直接检查已安装 App 的 `app.asar`：它与源码一样，在 HTTP `response` 回调中无条件 `unpipe`、销毁尚未结束的上传源，再结束请求。XAPI 的 import handler 则在调用 `stream_import` 读取归档之前发送 HTTP 200 响应头。两者组合使客户端提前停止发送，服务器继续等待 Content-Length 声明的剩余内容。相关官方源码与 Node 事件语义见 [XVA 规范](../xva-transfers.md)。

修复将提前关闭源流限制为重定向或拒绝响应，成功响应头允许原上传继续；源流和请求在响应头之后发生的错误继续传给响应读取方。响应关闭时释放残留源流。保留取消、超时、同源重定向限制与原 Task/最终对象校验。

新增可控流回环测试，服务器先发送 200 响应头，再等待剩余请求体。修复前确认源流被提前销毁，新增的读取错误测试也错误地等到超时；修复后通过。另覆盖提前拒绝、响应头之后取消和文件读取失败，并将导入重定向集成测试扩展到提前成功响应及超过 socket 缓冲区的 4 MiB 文件，检查服务端接收全部字节后仍须等待 Task 与 VM 后置检查。

验证：Node 24.22.0 / npm 11.19.1，HTTP 请求、TLS、XVA 集成、空闲超时和传输保护共 5 个测试文件、70 项通过，正式 focused gate 无 stderr、跳过或 todo；主进程类型检查、完整 lint 和 `git diff --check` 通过。修复未替换或重启正在运行的 App，未取消、重传或新建真实资源池任务。
