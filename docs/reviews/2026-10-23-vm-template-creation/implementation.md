# 模板创建与 Quick Create 合并记录

日期：2026-10-23。保留当前工作区已有修改，在原创建向导修复的基础上接手完成，并合入独立的快速创建服务。未提交、安装应用或操作真实资源池。

## 创建向导

| 原审查项 | 当前处理 |
| --- | --- |
| R01/R02：已有盘与 XML 导致额外建盘 | 主进程合并 VBD/VDI 和 XML，按设备号形成最终计划；clone/copy 后统一清除副本的 XML，再复用、移动、扩容或新增盘；最终读回数量、设备、SR、容量及启动标记 |
| R03/R04：重复光驱与启动设置 | ISO 安装优先复用有效光驱，弹出旧介质，清除额外安装光驱；HVM 调整光驱优先，硬盘和光驱启动标记按安装方式处理 |
| R05/R06/R07：安装方式与网络条件 | 区分 HVM PXE 和 PV eliloader URL；PV 设置实际安装仓库，含 RHEL NFS 形式；无安装元数据的 HVM 默认保留启动配置，仍可选择 ISO/PXE；PXE/URL 至少一张兼容网卡 |
| R08：小数字节 | GiB 换算四舍五入到整数字节，IPC 与主进程拒绝非正安全整数，输入和确认页避免展示二进制换算尾数 |
| R09/R10：数量和默认 SR | 仅统计真实硬盘及 XML 新盘；SR UUID 精确匹配，空 SR 使用池默认 SR，无法解析时要求选择 |
| R11：只读副本清理 | 以创建前 VDI 集合和独占关系确定本次资源，包含 RO 数据盘；不清理源盘，失败后报告残留或未知归属 |
| R13：CPU 拓扑 | 保留能整除目标 vCPU 数量的拓扑，否则先设每插槽 1 核；确认页展示最终值 |
| R12：网卡策略 | 按设备号继承 MTU、QoS、锁定及 IP 允许列表，重新生成 MAC；网络页和确认页展示实际策略，提交后发现模板策略变化则要求重读 |

资源读取与所选模板绑定，切换模板后的旧响应不能替换新计划；加载失败保留重试入口并禁止继续提交。系统模板保留明确删除盘/网卡的选择。自定义模板完整复制已确认的磁盘计划，提交前重新核对，不能悄悄增加用户未见的盘。

## Quick Create

资格、标记启用、VM 转模板标记、异步 clone → provision → 命名 → start、原池身份保护及未确认结果持久核对见[模板快速创建](../../vm-quick-create.md)。服务已从创建向导中分离，IPC 和返回 VM 引用的契约保持兼容。启动失败保留 VM，并与明确创建失败分开提示。

参考 XenAdmin、XO 和 XAPI 的固定版本与源码见[原审查报告](review.md)、[Quick Create 核查](../../research/xenadmin-quick-create.md)。普通向导清除 XML 后按计划建盘；Quick Create 保留模板 provision 语义，两条路径各自验证，不能机械共用建盘策略。

## 验证

使用 Node 24.22.0、npm 11.19.1。组件和有状态 XAPI 替身检查最终设备对象关系，覆盖磁盘/光驱复用、SR、安装、CPU、网卡、RO 清理、残留、旧响应、自动启动、重复提交和结果未知核对。最终执行结果记录在同目录的 `combined-verification.json`。

本地生产构建只生成 `out/`，不代表已安装应用更新。浏览器布局检查因自动审批服务故障及后续策略拒绝而未执行；全量测试中需要本地监听的用例受沙箱限制，监控和 VM 事件域另有失败，均需与聚焦通过结果分别看待。真实 XCP-ng 的存储分配、启动固件、RBAC 和失败清理仍待实机验收。
