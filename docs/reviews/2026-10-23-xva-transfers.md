# VM 与模板 XVA 流程修复记录（2026-10-23）

研究来源、格式限制与操作约定见 [XVA 规范](../xva-transfers.md)。以 Xen Orchestra 对照当前能力，以官方 XenAdmin 源码对照桌面向导，并核对 XAPI 的真实导出、导入和磁盘流格式。

## 缺陷与修复

| 缺陷 | 本轮实现 |
| --- | --- |
| 并发导出覆盖同一路径、选择路径后出现同名文件 | 标准化路径登记，已存在文件拒绝受理，验证后以排他硬链接发布；发布失败保留已验证 partial 的路径。 |
| 关机/checkpoint 响应丢失被当作明确失败 | 先返回操作 ID，后台执行 Async 准备，保存原 Task、VM UUID 与唯一检查点名；只读恢复，不重复关机或创建检查点。 |
| 配置恢复依赖已清除的 Task，新导入被全局锁住 | 已知 VM 可独立核对；操作历史与草稿分离，允许新建导入；写入开始后的恢复只读。 |
| unknown 停止观察且无法取消 | 保留未知状态和原操作，10 秒退避读取；未进入配置的导入及未结束的导出保留取消入口。 |
| 草稿可把旧引用提交给另一池或另一连接代次 | 绑定池 UUID、epoch 和连接 ID，变化后清空放置选择；IPC 受理再次核对。 |
| 预检只判断资源存在 | 复用创建流程的 live/enabled 主机、PBD、PIF、SR 容量与共同主机信息；受理、完整扫描后各检查一次；界面同样阻止无共同主机的组合。 |
| 模板、Home Server、磁盘结果未经核对即成功 | 核对对象 UUID、模板标记、affinity、VIF 设备/网络/VM 和 VBD/VDI 的 VM/SR 归属及数量。 |
| 只凭零尾判定归档完整，预览忽略缺失磁盘 | 检查 TAR 头与边界、XML、磁盘元数据、首尾块和内联 SHA-1/XXH64；支持稀疏中间块，逐条目让出事件循环。 |
| HTTP 长时间无进展也不结束 | 连接建立和 socket 连续 10 分钟空闲时中止本次连接，再核对原 Task；持续有活动的传输没有短总时长上限。 |
| 完成通知先于清理警告，旧记录可能永久清理中 | 一次清理尝试后发布终态，结构化返回 warnings；旧版终态恢复保留终态，未完成清理另行提示。 |
| 长传输及准备阶段锁住桌面 | 已受理操作可关闭弹窗，跨页面保留后台任务和取消入口；导入、导出面板限制高度并错开放置。 |
| 确认页缺少映射和结果入口 | 列出源文件、类型、池、主机、SR、CPU/内存、容量和每个 VIF 映射；确认原池后才可查看导入对象。 |

另核实并修复：checkpoint 的内存并不会因“已创建检查点”而自动进入默认导出。所有 `/export` 显式传 `preserve_power_state=true`，挂起归档的内存镜像参与容量估算、块校验和导入后 SR/容量核对，确认页解释导入后保持挂起。取消在 Async 准备响应前到达时，收到 Task 引用后继续发送原任务取消。

取消意图与上传是否开始也持久保存。重启后不再继续已取消的导出准备；新导入若明确在上传前退出，则结束记录并清理空 Task，避免等待一个从未执行的任务。缺少该阶段信息的旧导入继续保守观察原 Task。

## 本地验证

原始报告、日志与桌面截图保留在 `.scratch/import-export-fixes-2026-10-23/`。主要回归文件为 `xva-transfer-safety.test.ts`、`xva-archive.test.ts`、`xva-idle-timeout.test.ts`、`xva-http-data-plane.test.ts`、`vm-import-service.test.ts`、`VmImportDialog.test.tsx`、`ImportTransferPanel.test.tsx` 和 `ExportPanelPolling.test.tsx`。

- Node 与网页 TypeScript 检查通过，全仓 ESLint 诊断通过，main/preload/renderer bundle 构建通过。
- 完整工作区的 Vitest 诊断快照为 1886 项通过、0 失败。最后补齐持久取消及上传前退出边界后，相关服务、HTTP、IPC 和界面共 188 项重新执行，全部通过，其中 transfer safety 为 28 项；两组有重叠，不能相加。新增测试及数量已同步到测试清单，合并两次实际收集结果核对。
- Chrome 加载当前 renderer，经受控 preload fixture 操作真实界面；1024×720、1280×800、1440×900 共 21 项检查通过，没有页面异常。覆盖 VM/模板确认、后台准备、unknown 恢复、新草稿和长消息下双面板同时显示；未发现面板相互重叠或视口越界。
- XXH64 单纯计算的本机样本为 16 个 1 MiB 块，约 125 ms（约 128 MiB/s）；这只说明该计算样本，不代表真实磁盘或资源池吞吐。

## 验证边界

项目固定 Node 24.22.0 / npm 11.19.1。当前 shell 为 Node 26.0.0 / npm 11.12.1，本轮直接诊断使用捆绑 Node 24.22.1。因此上述检查不记为正式工具链 gate 通过；没有修改版本约束或伪造工具链版本。

当前工作区已有其他未提交改动，本轮保留这些内容；全量诊断覆盖的是执行时的整个工作区。构建生成本地 bundle，没有安装应用、提交代码或执行真实资源池写操作。真实 VM/模板往返、checkpoint 恢复运行、存储后端、大文件、TLS 与成员重定向以及断线/重启时序仍需实机验收。OVA/OVF、磁盘镜像转换、压缩和旧式末尾校验表格式不在本轮扩展范围。
