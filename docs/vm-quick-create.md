# 模板快速创建

2026-10-23。实现参照项目内的 XCP-ng XenAdmin 副本，版本和原始资料见[核查记录](research/xenadmin-quick-create.md)。普通创建向导使用明确的磁盘和网卡计划；快速创建沿用模板配置，执行模板原有的 provision 逻辑。

## 模板条件和入口

虚拟机列表的用户模板「操作」菜单提供以下入口：

| 模板状态 | 菜单行为 |
| --- | --- |
| `other_config.instant` 严格等于字符串 `true` | 「快速创建 VM」，提示会沿用配置创建并启动 |
| 缺少标记或值不同 | 「启用快速创建」，仅写入标记并读回验证，刷新该资源池的模板 |
| 锁定、存在当前操作、未停止、XAPI 不允许 clone 或管理员禁止 clone | 禁用操作并显示具体原因 |
| 系统默认模板 | 不提供快速创建或启用入口，继续使用创建向导 |

主进程在操作前重新读取对象，要求普通用户模板、非快照、非控制域、Halted、无当前操作、允许 clone。前端与主进程共用资格判断。启用标记也执行这些检查。停机普通 VM 原地转模板、从快照另存新模板会写入 `instant=true`；再次标记已是模板的对象保持原有幂等行为，不自动修复历史模板。

`instant` 是客户端资格标记，不是 XAPI 的 provision 参数，也不是“已安装可启动操作系统”的检测结果。启用前应准备好系统、启动配置、磁盘、网络和所需存储。它不要求 Guest Tools、cloud-init、固定磁盘数或共享 SR。存储容量、权限、主机和设备的实际可用性由 XAPI 检查。

## 执行和结果

1. 以原连接的资源池 UUID、连接代次和客户端为边界，读取模板身份及资格；同一模板在多个连接下也只允许一个正在执行的本地请求。
2. 提交并观察 `Async.VM.clone`，得到副本后核对其身份；提交并观察 `Async.VM.provision`，核对副本已变为停止的普通 VM。
3. provision 后读取已有名称，分配 `模板名 (n)`，移除 `HideFromXenCenter`，读回确认。本进程并行创建使用名称预留；其他客户端仍可能同时使用相同名称，XAPI 名称本身不唯一。
4. 按副本当前能力提交并观察 `Async.VM.start(false, false)`，读回确认 Running 后才提示“已创建并启动”。

快速创建不提供目标 SR、ISO、CPU、内存、硬盘或网卡选择，不重写模板的计算或设备配置。模板若含 `other_config.disks` 或 `postinstall`，继续交由 provision 处理；不会套用普通创建向导清除 XML、再按明确计划建盘的策略。模板作者需确保这些配置与已有磁盘匹配。

行内显示「处理中...」并防止重复点击。clone、provision、start 的服务器任务可在任务页查看；大型 clone 不使用固定十分钟的工作流截止时间，任务读取失败仍有限次重试。应用不会把任务成功单独当成最终 VM 状态已确认。

## 失败与再次操作

- 创建完成后启动失败或无法确认：保留 VM，使用警告反馈给出 VM/Task 引用，不将其回滚删除。
- clone 或 provision 明确失败：报告失败及已知的副本/Task 引用，保留已有对象供检查，不自动销毁其磁盘。
- 写入响应或最终读回未确认：在本地 `vm-quick-creates.json` 保留原池、模板 UUID、阶段及已知的 Task/VM 身份。记录先于写入保存；再次操作或重启应用后只核对原尝试，不重放 clone、provision、设置或 start。
- 已知原 start 完成且原 VM 仍是 Running 时，返回原 VM；其他可确认的未完成副本报告其状态，并结束本次核对，用户检查现有对象后再决定操作。
- clone 响应丢失且没有 Task/VM 身份时，不能凭名称认领任意对象。记录保持“结果未确认”，持续阻止重复创建；需要先核对原池任务和副本，当前界面不提供强制清除这条记录的按钮。
- 连接切换或重连后，旧执行不会继续提交后续操作，也不会用原结果刷新替换后的资源池。

## 验证边界

单元和组件测试覆盖资格、异步调用顺序、命名、自动启动、只启用标记、防重复、连接代次、保留副本、未确认任务及重启后核对。正式验收仍需真实 XCP-ng 的已安装用户模板、多盘/光驱模板、不同 SR、RBAC、存储满和中断场景。源码测试与本地构建不表示已更新安装应用或通过实机验收。

## 列表一致性（2026-11-04）

clone 副本在 provision 前仍是模板，可能被独立的模板清单请求缓存。旧实现仅在模板事件及删除事件到达时更新模板清单；副本变成普通 VM 的事件只更新 VM 清单，直接拼接后产生相同 React key，导致重复行。普通 VM 刷新不能清除另一份模板缓存，页面重新挂载才会重读，因此出现刷新无效、切换页面后恢复的现象。组件回归已复现重复 key 与重复行。

当前在完整事件首次把对象加入 VM 清单时，同时更新模板清单；后续普通 VM 属性更新不重复触发模板读取。两份清单合并时再按“连接＋对象引用”保证一对象一行，当前 VM 优先，覆盖事件遗漏、模板读取尚未返回或失败保留旧缓存的场景。不按名称去重，不修改服务器对象或创建流程。

依据：[XAPI 对象引用与事件语义](https://xapi-project.github.io/xen-api/usage.html)说明名称不保证唯一、事件包含对象快照；[XenAdmin 快速创建实现](https://github.com/xcp-ng/xenadmin/blob/ba43130ffb30d05d1eb40187b8ef9f2de111468a/XenModel/Actions/VM/CreateVMFastAction.cs#L64-L95)确认 clone → provision → 命名的生命周期。本次也核对了 [XO 的 VM 列表与排序](https://docs.xen-orchestra.com/manage-your-infrastructure/manage_infrastructure)和 [XenAdmin 自然顺序比较](https://github.com/xcp-ng/xenadmin/blob/ba43130ffb30d05d1eb40187b8ef9f2de111468a/XenModel/XenSearch/Sort.cs#L119-L157)；表头排序规则与取消分页见[前端规范](frontend-spec.md)。
